# Command contracts

The shared command types live in `crates/orbit-core`. TypeScript bindings are generated by `ts-rs` during `cargo test -p orbit-core`; JSON Schema is produced from the same Rust types with `schemars`.

## Implemented command

| ID | Risk | Parameters | Result |
| --- | --- | --- | --- |
| `screenshot.capture` | Mutating (writes clipboard) | `ScreenshotRequest` | Captured dimensions and monitor count |

`ScreenshotRequest.mode` is `fullscreen` or `region`. A fullscreen request without `monitorId` captures and composites all displays. Setting `monitorId` limits capture to that display. A region request uses `monitorId` (or the primary display) and requires `x`, `y`, `width`, and `height`; coordinates are relative to the selected display. Captures are written directly to the system clipboard and are not saved to disk.

The command rejects empty regions, display IDs that do not exist, and captures exceeding the in-memory pixel limit. Native capture and clipboard failures are returned to the caller.

## Invocation and audit

The Tauri UI invokes `execute_command` with a `CommandRequest`. The source is assigned by the host as `orb`; it is not supplied by the UI. Each supported or rejected request is recorded in the app-data SQLite `audit_log` table with its command ID, a SHA-256 hash of parameters, result, duration, and timestamp. The database uses `PRAGMA user_version` migrations.

The command catalog is available through `get_command_catalog`. Unsupported IDs return an error response and are audited. If the audit write itself fails, the invocation reports that failure rather than claiming success.

The command catalog, audit schema, and capability set are still under development. Do not treat unimplemented roadmap commands as available.
